# Markdown 格式与编辑器边界

格式版本：`1`。本文落实 OpenSpec 任务 1.6，代码位于 `packages/editor/`，Web 和后续原生 UI 使用同一编辑器包。当前编辑体验尚未接入账号或服务端保存，Web 入口提供 [IndexedDB 预览草稿恢复](web-drafts.md)。独立编辑器组件本身不负责持久化。

## 支持语法

支持段落、一级至六级标题、粗体、斜体、删除线、无序/有序/任务列表及嵌套列表、引用、行内代码、围栏代码块、软换行和硬换行、行内链接、图片引用、水平分隔线。语言标识可以附加在代码围栏后；暂不支持额外的代码块 metadata。

不支持原始 HTML、表格、脚注、引用式链接/图片和链接定义。导入或从源码切换时明确拒绝这些结构，保留源码供用户调整，禁止让不支持的节点被富文本解析器静默删除。数学、指令等未解析扩展按普通源码文本对待，不宣称具有扩展语义。

## 规范化规则

- Milkdown 的 CommonMark 与 GFM 解析/序列化处理受支持的富文本投影，GFM 表格和脚注被入口校验禁止。
- LF 换行；非空文档以一个换行结束；空文档输出空字符串。
- 无序列表默认使用 `-`，新建粗体默认使用 `**`，新建斜体默认使用 `*`；导入的等价粗体/斜体标记保留，避免无意义改写。水平分隔线使用 `---`，代码采用围栏形式，列表使用统一缩进配置。
- 规范化可能改变等价排版形式，但不能丢失文本、格式语义、链接或图片引用。不同客户端以同一套 golden fixtures 验证，重复往返不得继续改写。
- 编辑器 JSON、HTML 和 SQLite 行模型均不能取代 Markdown 成为内容契约。

当前 golden fixture 在 `tests/fixtures/markdown/supported.md`，覆盖中文、格式、列表、任务、引用、代码、链接、图片及分隔线。测试另覆盖缺省图片标题/alt、Windows 换行、转义与普通代码块。

## 安全与资源限制

源码作为文本显示，禁止直接使用 `v-html`。Markdown AST 入口拒绝 HTML 与不支持节点；链接与图片 URL 校验允许 HTTP、HTTPS、mailto、相对路径和页内引用，拒绝活动协议、协议相对地址、反斜杠、控制字符及带账号密码的 URL。

图片在当前预览中显示不发起网络请求的占位内容，原始地址、alt 与 title 仍保存在 Markdown 中。附件鉴权与下载接入前不自动加载远端图片。编辑区内点击链接不触发导航。

粘贴读取剪贴板纯文本并按受控 Markdown 处理；剪贴板任意 HTML 和文件拖放不进入解析器。当前没有富文本剪贴板保真或文件上传承诺。编辑事务同样校验输出，源码校验失败不替换已有富文本内容。

编辑预览使用 512 KiB UTF-8 输入上限防止无界解析，它是原型资源边界，不是最终笔记或账号配额。输入法 composition 期间不切换模式、不执行工具栏格式命令；真实中文 IME、选区、浏览器布局仍需手工/浏览器回归，合成事件测试不能替代这些验证。

## 验证

```text
pnpm test:editor
pnpm check
```

完整 `pnpm check` 包含编辑器测试，现有 Web CI 会执行相同命令。Milkdown 接入依据其 [Kit 文档](https://milkdown.dev/docs/guide/using-milkdown-kit)、[源码宏](https://milkdown.dev/docs/api/utils)和 [Listener 文档](https://milkdown.dev/docs/api/plugin-listener)。
