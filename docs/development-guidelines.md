# 开发规约

本规约依据 [AGENTS.md](../AGENTS.md) 和 [OpenSpec 变更](../openspec/changes/add-self-hosted-notes-platform/)制定，与 [技术架构](technical-architecture.md)配套使用。“必须/禁止”为提交与评审要求，“建议”为可在具体任务中调整的实现方案。工程尚未搭建，下面标为“待建立”的命令不能视为已可运行。

## 1. 变更流程

1. 开始工作前阅读对应 proposal、design、能力 spec 与 tasks，选择最小可验收任务。
2. 架构、同步、安全、工作流及其他中大型变更必须先通过 OpenSpec 记录并评审；提案与实现分开，不以文档生成或 CLI 校验成功代替批准。
3. 只实现当前任务需要的内容。禁止复制旧 Electron 架构、引入未要求的服务或提前实现后续产品范围。
4. 行为偏离规范时先更新 OpenSpec，不能以代码事实反向替代规范。
5. 完成任务需同时交付代码、最小相关验证、文档和 CI 命令；满足验收后再勾选任务。
6. 保存用户既有修改，数据库、生产数据和凭据不能作为可随意覆盖的测试素材。

## 2. 模块和契约

- 组件通过明确领域接口操作数据；HTTP/Tauri 入口不堆积业务逻辑或事务。
- 服务端仓储、原生仓储、各自迁移独立维护。共享包仅包含领域基础类型、协议和纯逻辑。
- 所有 HTTP、WebSocket、Tauri command、文件、导入、配置和持久化恢复入口做运行时验证。生成的 TypeScript 类型不能替代运行时校验。
- owner、设备和服务器配置从可信会话上下文取得，不能信任 payload 的身份声明。
- 公开契约变更更新 OpenAPI、生成类型、JSON fixtures 与版本兼容性测试；生成文件禁止手工修改。
- 查询有界，操作超时、取消与重试语义明确。未知操作显式报错；受支持可选字段按契约兼容处理。

## 3. TypeScript 和 Vue

- 启用 `strict`；建议同时启用 `noUncheckedIndexedAccess` 与 `exactOptionalPropertyTypes`。
- 禁止 `any`、`@ts-ignore`、双重类型断言和通过关闭检查绕过错误。外部输入先使用 `unknown`，经校验收窄。
- 使用明确的领域 DTO、判别联合和错误码；revision/cursor 不转换为 JavaScript `number`。
- Vue 组件关注交互，composable 管理用例状态，适配器管理平台差异。共享包不得直接导入平台专用 API。
- 编辑器实例和大型文档避免无意义的深度响应式；监听、事件、计时器和订阅必须释放。输入法 composition 期间不得破坏性重写内容。
- 界面明确区分草稿、本地提交、服务端提交、同步中、冲突和失败；处理取消、会话过期与网络中断。
- 用户可见文本统一使用 i18n，先建立简体中文资源；禁止通过字符串拼接生成需要翻译的句子。
- Markdown 不直接交给未净化的 `v-html`；链接、图片与导入内容使用同一套受控规则。
- 基础界面支持键盘操作、可见焦点和可访问名称；回归验证中文 IME、高 DPI 与长文档。

## 4. Rust

- 使用新类型表达 ID、revision、cursor 和受限路径等不同语义；使用 enum 表达状态和可恢复错误。
- HTTP 与 command handler 薄化；错误转换保留内部诊断分类，公开响应不泄露实现详情。
- 可失败路径返回 `Result`；生产请求与恢复路径禁止无依据的 `unwrap`、`expect` 或 panic。
- 禁止无必要的 `unsafe`；确有必要时记录安全不变量、作用域和验证证据，并专项评审。
- 阻塞 SQLite、文件 I/O 和密码哈希不得阻塞异步运行时；选择明确的异步接口或受限阻塞任务执行器。
- 不跨 `.await` 持有数据库写事务或不必要的锁；锁顺序、任务取消和关机等待有明确策略。
- 资源释放与失败清理由作用域或状态机保障；不通过忽略错误把部分操作报告为成功。
- Tauri commands 是保存笔记、查询、导入、同步等粗粒度操作，禁止 `execute_sql`、任意读写路径等万能命令。

## 5. 数据、同步和迁移

- SQL 参数化，必要约束同时落入数据库；每个连接验证外键与数据库运行配置。
- 原生保存正文和 Outbox 同事务；服务端提交实体、变更流和 mutation 结果同事务；Pull 整页和游标同事务。
- 幂等重试保留原 mutation ID 与载荷；同一 ID 不同载荷拒绝。连续编辑实现可验证的因果顺序。
- Pending 编辑不能被 pull 覆盖；过期 revision 保留冲突副本。删除传播、保留期与游标过期必须有显式恢复方案。
- 不能用设备时间、最后到达的请求或无条件 upsert 替代 revision 前置条件。
- 附件文件与数据库跨资源一致性使用显式状态和恢复流程；测试文件已发布但事务失败等中间状态。
- 迁移编号不可重用，已发布迁移不可改写。变更 schema 前检查兼容性与恢复点，失败停止运行。
- 测试覆盖旧 schema 升级、未来 schema 拒绝、迁移中断及 image-plus-backup 回滚；不以降级迁移代替恢复。
- 导入定义重复处理与单项/批次事务策略，输出逐项报告；导出可直接用 Markdown 和文件工具读取。
- FTS、缓存和临时上传可重建；用户正文、未同步操作与冲突不能作为缓存清理。

## 6. 安全与隐私

- 认证不等于授权；笔记、附件、设备、同步、导出和管理操作分别验证 owner 或管理权限。
- Cookie 会话配套 CSRF；设备凭据独立撤销。刷新凭据禁止进入 WebView、浏览器存储、配置文件或日志。
- 密码仅以 Argon2id verifier 保存；初始化权限一次性生效，登录和初始化统一错误并限流。
- 不忽略 TLS 校验，不自动向重定向的其他 origin 发送凭据；非 HTTPS 开发例外仅限显式可信开发配置。
- 文件路径解析后验证限定根目录；防止绝对路径、`..`、符号链接及归档穿越，限制解压后大小和文件数量。
- 附件 MIME、扩展名和客户端声明均不构成可信授权；限制危险内联类型和下载响应，校验内容完整性。
- 日志禁止包含笔记正文/标题、原始文件名、密码、令牌、Cookie 和备份敏感内容；第三方库调试日志同样审查。
- 错误日志保留关联标识和受控错误分类；测试验证字段脱敏，不在 CI 上传真实用户数据。
- 安全依据参考 [OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)与 [Tauri 权限边界](https://v2.tauri.app/security/runtime-authority/)。

## 7. 测试策略

测试围绕可观察行为、不变量和失败恢复，避免只重复实现细节。使用临时独立目录与数据库，不能连接真实账号或修改开发者常用数据。对于关键存储行为使用真实 SQLite，不完全依赖 mock。

| 变更类型 | 最小相关验证 |
| --- | --- |
| 协议/DTO | 合法和非法 JSON、精度、未知字段/操作、相邻版本 fixtures |
| Markdown/编辑器 | 规范化幂等、往返语义、不支持语法、恶意 URL、中文 IME |
| 仓储/API | 外键和唯一约束、owner 越权、并发旧 revision、有界查询 |
| 同步/原生保存 | 提交后丢响应、重复 mutation、连续离线编辑、重启、整页回滚、冲突和删除竞争 |
| 附件/导入 | 路径逃逸、恶意归档、配额、完整性、中断和孤立文件恢复 |
| 会话/设备 | CSRF、跨用户 ID、撤销即时生效、刷新响应丢失与重放 |
| 备份/迁移 | 活跃写入期间备份、附件闭包、缺失/损坏归档、恢复后设备重连、旧/未来 schema |
| Web/Windows | 草稿恢复、会话到期、离线、中文 IME、睡眠唤醒、代理、高 DPI |
| Docker/发行 | 新安装、卷保留替换、第二实例拒绝、升级回滚、amd64/arm64、安装与签名校验 |

跨端测试必须覆盖 Web→Windows、Windows→Web、两个设备并发编辑和首次拉取；网络通知丢失不能阻止最终通过 pull 收敛。性能测量记录硬件、数据规模、耗时分布和内存，不设未经测量的发布阈值。

## 8. 验证命令与 CI

当前可执行的规范验证命令：

```text
openspec-cn validate add-self-hosted-notes-platform --strict
```

Windows PowerShell 若受 `.ps1` 执行策略限制，使用等价的 `openspec-cn.cmd validate add-self-hosted-notes-platform --strict`，不修改系统执行策略。

脚手架任务 2.3–2.4 必须建立并记录以下命令。它们目前是目标接口；实际建立后才可作为验收证据。

| 层 | 待建立命令 | CI 要求 |
| --- | --- | --- |
| Rust 格式 | `cargo fmt --all -- --check` | 每个相关 PR |
| Rust lint | `cargo clippy --workspace --all-targets --locked -- -D warnings` | 每个相关 PR，按平台适用 targets 分矩阵 |
| Rust 测试 | `cargo test --workspace --locked` | 相关模块及集成测试，按平台分矩阵 |
| 前端安装 | `pnpm install --frozen-lockfile` | 固定工具链、锁文件安装 |
| 前端静态检查 | `pnpm typecheck`、`pnpm lint` | 脚本覆盖 apps 与 packages |
| 前端测试 | `pnpm test` | 脚本在 CI 非 watch 运行 |
| Web 构建 | `pnpm build:web` | 验证生产资源与 API 同版本 |
| 协议/浏览器/恢复 | 在对应任务注册具名脚本 | 任务 3、7、8、10、11 落实可复制命令 |
| Docker/Windows | 在对应任务注册构建与 smoke 命令 | Linux amd64/arm64 与 Windows runner |

建议前端使用 Vitest、Vue Test Utils 与 Playwright；具体依赖和版本在工程任务中固定。平台特有 crate 不能强行在所有平台执行相同 targets。检查范围按变化选择，关键同步、安全和恢复不变量不得以低风险文档检查替代。

CI 只授予必要权限；外部贡献测试不取得发布签名密钥。发布采用独立受控流程，依赖和工作流版本固定，镜像与安装包提供版本、校验值和来源信息。工具升级必须验证生产构建与协议 fixtures。

## 9. 提交、评审和完成标准

建议提交信息使用 `feat`、`fix`、`docs`、`test`、`refactor` 等清晰类型，一次提交围绕一个可解释目的。PR 说明问题、行为变化、关联 OpenSpec 任务、实际执行的验证及已知限制。

完成条件：

- 行为符合对应规范场景，未扩大首发范围。
- 类型、格式、lint 和最小相关测试通过，实际命令进入文档与 CI。
- 协议、数据库、附件、权限或恢复变化已补充相应 fixtures/故障验证。
- 无敏感日志、未经校验边界、静默覆盖或无恢复路径的数据修改。
- 用户文本通过 i18n；接口和平台行为可理解、可恢复。
- 文档、配置示例、兼容性说明与任务状态准确；未运行检查须明确标注。

发布前必须完成任务 14 的威胁评审、数据丢失评审、性能测量和兼容性政策。签名与更新清单验证不能只用开发构建代替；正式版本不加载远程 UI 代码。
